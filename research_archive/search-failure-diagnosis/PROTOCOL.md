# 原始 FocusTrack 搜索区域诊断

本分支从 `main` 的 `10d7c28` 开始，独立于此前策略学习实验。保持原模型、SRA、坐标还原、模板与 Hann 规则，仅新增离线分析与可复现的同状态裁剪实验。使用官方完整 val，test 不使用。本轮属于诊断，不能据此选择并宣称一个在独立数据上验证的新方法。

## 1. 裁剪遗漏与历史误差

- 使用原始 `exist=1` 且 GT 框合法的帧；`exist` 不等同于无遮挡或清晰可辨。
- 分开统计目标中心出界、中心在内但框不完整、框完整覆盖。完整覆盖阈值 0.999，另报告 0.95 敏感性统计。
- 中心出界事件取连续出界段起点。区分前一帧 IoU≥0.5、<0.2、中间区间以及前帧无有效 GT。
- 当前目标相对上帧预测中心的偏移满足：`当前GT中心 - 前帧预测中心 = GT帧间位移 - 前帧中心误差`。
- 用前帧 GT 中心替换预测中心、保持预测框尺寸和因子，检查当前中心是否会被覆盖；再用完整前帧 GT 框复查，以区分中心与尺度的影响。这是几何参照，不是部署方案或完整因果结论。
- 图像位移不直接等于目标自身快速移动；相机运动、目标运动及其混合需要背景配准与人工检查，本轮不凭框轨迹强行命名。

## 2. 分支信号和恢复延迟

原代码仅当存在概率 `<0.8` 且原始响应峰值 `<0.5` 同时成立时触发扩张。下一帧因子为 `min(当前因子+1, 8)`，并关闭 Hann；其他情况将因子恢复为 6、打开 Hann。当前帧因子由上帧决定，当前帧输出首次影响下一帧。

存在概率低于控制阈值不等同于二分类错误；存在概率高不证明定位了正确目标。SRA 实际还使用定位分支的峰值。四种信号组合分别报告。

预测框无论可靠性如何都会更新，故搜索中心和基于面积的裁剪大小也可能漂移。必须分别记录“触发扩张”“因子增大”“裁剪像素边长改变”。因子到 8 后仍可能持续触发但无法继续增大。

定位失败阈值 IoU<0.2。持续失效事件要求连续五帧有效可见且低 IoU，事件直到连续三帧 IoU≥0.5 确认恢复才结束，中间的短暂恢复不重复计数。连续有效可见性中断或序列结束时截断。中心出界事件与持续失效事件是两种视角，不能相加当作独立样本。

记录首次扩张信号、首次实际增因子、首次框完整覆盖、首次 IoU≥0.5、三帧稳定恢复。首次覆盖之后的定位等待单独计算；也报告覆盖过但始终未恢复的事件。恢复时间均值仅在已恢复事件上计算，须同时报告未恢复和提前截断数量。30 帧恢复率在提前截断事件存在时是观测下界。

属性 `OC/FM/TS/LR/IC/DBC` 仅在该序列提供同长度逐帧标注时统计，缺失不补零。属性相关性不直接证明遮挡、热交叉等机制。另对前帧IoU≥0.5的出界失败图像对做背景运动检查：排除GT附近，ORB匹配、ratio阈值0.75、局部仿射RANSAC阈值3像素，要求至少20个内点、内点率≥0.5、中位残差≤2像素、内点凸包面积≥图像面积5%。目标中心背景预测残差不超过GT位移30%才标为背景运动一致。未过质量门槛标为未知；即使通过也不当作相机因果证明。

## 3. 缩小仍覆盖是否有用，历史能否支持

第一组枚举基线框完整覆盖但 IoU<0.2 的全部帧，排除初始化。第二组每序列均匀采至多32帧，第三组从在线历史门控为真的时刻每序列均匀采至多32帧。三组去重执行，但分别汇总，正常帧对照用于测量误伤。

从原日志重建第 t 帧前的完整有效状态：固定初始模板、前帧预测框、因子、Hann、帧号与标志。原跟踪器无模板更新、时序视觉缓存或隐藏状态。每个任务先使用原裁剪复现原预测、存在概率、峰值与因子转移，再测试因子2/3/4/5（仅小于当前因子的动作），所有动作保持预测中心和 Hann 不变，不使用 GT 平移中心或修正预测框。每条序列做 A/B/A 复查；跟踪器保持 eval 和冻结，前后比较全部参数及缓冲哈希。

缩小同时改变目标分辨率和背景范围，不能只把收益解释为分辨率。GT 只用于事后评价覆盖与 IoU。选“仍完整覆盖且 IoU 最高”的候选是 oracle，只作为机会参照。各固定因子在均匀样本、在线门控样本上的收益和损害单独报告，并按序列均值做10,000次配对 bootstrap；这些是同状态单步实验，不是闭环跟踪指标。

两种历史定义均只看截至 t-1 的五帧：

- GT事后可靠：五帧均有效可见且 IoU≥0.5。
- 在线可用门控：五帧存在概率≥0.8、原峰值≥0.5，预测中心相邻移动不超过当前基线裁剪边长的25%，预测框平方根面积最大/最小≤1.5。该门控是预先固定的诊断对照，不是训练或调参结果；稳定跟错仍可能通过。

判断顺序为：存在可恢复机会 → 机会前历史确实可靠 → 因果观测能区分机会与危险帧 → 闭环策略收益。前三者不能替代第四步；本轮不训练 GRU 或 SLT。

## 运行

```bash
python tracking/diagnose_search_failures.py prepare
python -m unittest tracking.test_search_failure_diagnosis
python tracking/diagnose_search_failures.py intervene --device cuda:0 --shard 0 --shards 4
python tracking/diagnose_search_failures.py intervene --device cuda:1 --shard 1 --shards 4
python tracking/diagnose_search_failures.py intervene --device cuda:2 --shard 2 --shards 4
python tracking/diagnose_search_failures.py intervene --device cuda:3 --shard 3 --shards 4
python tracking/diagnose_search_failures.py report
python tracking/visualize_search_failures.py
```

四个干预命令可同时执行。环境为本机 `focustrack` conda 环境。默认输出 `output/search_failure_diagnosis/20261016/`，与旧实验完全分开。原轨迹输入为已审计并复现的 `output/search_policy/baseline_val_v2_full.json`；准备阶段核对90序列全集、原GT、每帧裁剪几何、因子及Hann转移。输入轨迹本身不纳入源码提交，原始记录保留在本机旧实验备份中。
